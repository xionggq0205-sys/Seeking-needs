## 1. 背景与要解决的问题

我长期想做海外付费网站，通过不断寻找市场需求、开发不同的付费站来变现。当前最核心的痛点是：**无法稳定、有效地找到真实的市场需求**。过去常见的失败模式是"先写两周代码，上线后才发现没人要"。

这个工具要解决的，不是"帮我想一个好点子"，而是：

- 把"找需求"从**靠灵感猜**，变成**找用户已经暴露出来的真实信号**；
- 解决"用什么语言搜"的问题——中文思维直接翻译成英文关键词，会漏掉真正的用户表达；
- 把分散在各平台的讨论，整理成**可判断、可追溯**的需求结论；
- 对有潜力的方向，进一步给出竞品分析、用户画像、市场规模、定价和推广建议，直到能做 GO / NO-GO 决策。

> 方法论来源：本工具的分析逻辑主要参考两篇实战文章——(1)「找外国人需求」的信号方法论（信号四分类 + 扩词），(2)「3 小时 BRD 调研」流程（趋势 → 竞品差评 → 画像 → 市场规模 → 定价 → 决策）。本文档把它们的人工流程产品化、自动化。

## 2. 产品目标与非目标

### 2.1 目标
- **首要目标（V1）**：让我能在一次操作内，对一个方向得到一份"靠谱的"需求判断——分类清晰的信号、可追溯到原帖的证据、跨平台去重后的痛点清单。
- **进阶目标（V2-V3）**：能主动发现我没想到的机会、追踪痛点冷热变化，并产出完整 BRD（功能 / 定价 / 推广 / GO-NO-GO）。
- **长期可选目标**：验证有效后包装成对外付费产品（需先解决商业数据源成本与合规，见 §10）。

### 2.2 非目标（明确不做）
- 不承诺"用了就一定能找到赚钱项目"——它是辅助判断工具，不是保证。
- 不替用户做最终决策，也不替用户做产品和商业模式。
- V1 不做用户系统、登录、计费、多租户。
- V1 不追求平台覆盖广度（多平台、大数据量是最贵、ROI 最低的，后置）。
- 不做中文市场需求（聚焦海外 / 英文市场）。

### 2.3 成功标准
- **V1 成功标准**：在 1-2 周内，工具至少帮我筛出 **1 个**"证据充分、值得做 MVP"的真实方向（满足 §9 的 GO 条件 ≥3 条），且我对该方向的理解明显强于"拍脑袋"。
- **过程指标**：单次验证报告中，≥80% 的关键结论都能点到原始出处；噪音（广告 / 榜单 / 目录站）占比低。

## 3. 目标用户

- **V1 唯一用户**：我自己（做海外付费站的独立开发者）。
- **未来对外用户画像**：想做出海工具站 / 轻量 SaaS / AI 工具，但"找不到做什么"或"总靠灵感选题"的独立开发者；以及"已有想法、想先看有没有真实需求证据"的人。

## 4. 核心方法论（产品逻辑的理论基础）

以下是分析引擎必须遵循的判断框架，后续功能需求都建立在此之上。

### 4.1 找信号，不找灵感
需求判断的依据是用户**已经留下的行为**：搜了什么、在哪抱怨、找什么替代品、为什么骂现有产品、有没有掏钱、问题是否重复、场景是否具体、能否用小产品验证。

### 4.2 信号四分类
| 信号类型 | 含义 | 典型来源 | 强度 |
|---|---|---|---|
| 关键词信号 | 用户在搜什么（工具类长尾词） | Google 搜索 / Trends、关键词工具 | 中 |
| 抱怨信号 | 用户在骂什么、在求助什么 | Reddit、X、Hacker News、GitHub Issues、Product Hunt、应用商店差评 | 中（比关键词更早期） |
| 替代品信号 | 用户在找 "X alternative"、嫌现有方案贵 / 难用 | 同上 + 评测站 | 偏强 |
| 付费信号 | 已经有人花钱解决这个问题 | Fiverr、Upwork、Gumroad、Etsy、Toolify、长期投广告的站、流量持续上涨的工具站 | **最强** |

### 4.3 信号强度三档
- **弱信号**：有人讨论、有兴趣，但场景不清晰。
- **中信号**：多人重复抱怨同一问题，且有明确使用场景。
- **强信号**：有人主动找工具 / 找替代品，甚至出现付费、外包、订阅、投广告等行为。

### 4.4 真痛点判定规则（可直接落地）
> **同一痛点出现 ≥3 次，且来自 ≥2 个不同平台，才算"真痛点"。** 1-2 次按噪音处理，标记为"未验证"。

避免单平台"回音壁"（如 Reddit 天然偏反付费）。频次最高的不一定最好——要找"频次不低、但竞品一直没解决好"的痛点，那是切入点。

### 4.5 证据链优先
一条"我觉得有机会"价值很低；一条带证据链的需求（有人搜 + 有人抱怨 + 有人找替代品 + 有人付费 + 现有产品差评集中在同一问题 + 可用小工具解决）才值得认真看。**每条结论都必须能回到原始出处。**

## 5. 功能性需求（FR）

按模块组织，并标注所属阶段（V1 / V2 / V3）。

### FR-1 输入与扩词（V1）
- FR-1.1 用户输入一个方向：可以是中文或英文的关键词、市场、功能或产品想法。
- FR-1.2 系统先调用"扩词"步骤，把模糊输入转成更接近真实英文语境的搜索集合，输出固定 schema：
  - `englishSearchQuery`：简短英文搜索主题
  - `keywords`：直接关键词变体
  - `relatedTerms`：相邻问题词 / 用户人群词
  - `derivativeTerms`：同义表达 / 常见共现短语
  - `sourceHints`：平台相关词、话题标签、repo 词、社区词
  - `excludedTerms`：需要排除的歧义词（避免结果变脏）
- FR-1.3 扩词结果与意图词（pain / tool / payment / alternative）组合，生成最终搜索查询集。
- FR-1.4 扩词结果对用户可见、可手动编辑后再检索（人工校准）。

### FR-2 数据采集（V1 起，逐步扩展）
- FR-2.1 **数据源采用可插拔适配器架构**：每个数据源是一个独立 adapter，新增 / 移除 / 替换某个源不影响其他源（为将来把免费源替换成商业源做准备，见 §10）。
- FR-2.2 V1 接入的免费 / 低成本源（详见 §8）：Reddit（免费层）、Hacker News（开放 API）、Google Trends。
- FR-2.3 V2-V3 逐步加入：Product Hunt、G2 / Capterra / Trustpilot 差评、Chrome 应用商店差评、App Store 差评、Fiverr / Upwork / Gumroad（付费信号）、SimilarWeb（免费版反推流量）。
- FR-2.4 每个 adapter 必须遵守对应平台的速率限制与使用条款（见 §7 合规）。
- FR-2.5 采集结果带元数据：来源平台、原始链接、发布时间、互动量（点赞 / 评论数等）。

### FR-3 清洗与聚类（V1）
- FR-3.1 过滤噪音：广告、榜单 / listicle、目录站、明显的机器人 / 营销内容、重复内容、弱相关内容。
- FR-3.2 跨源去重。
- FR-3.3 把相似讨论聚类成"痛点主题"，每个主题提炼：使用场景、用户不满、可能的产品方向。

### FR-4 信号分类与需求打分（V1）
- FR-4.1 给每条 / 每簇信号打上四分类标签（关键词 / 抱怨 / 替代品 / 付费）。
- FR-4.2 按 §4.3 给出信号强度（弱 / 中 / 强）。
- FR-4.3 输出一个**需求分数**（综合信号强度、重复频次、跨平台数、是否有付费信号）。
- FR-4.4 应用 §4.4 规则：跨平台 ≥2 且频次 ≥3 的标"真痛点"，否则标"未验证"。

### FR-5 证据链与可追溯（V1，核心信任点）
- FR-5.1 每条痛点 / 结论附带证据：原帖链接、平台、发布时间、互动量、关键原文片段（短引用，注明出处）。
- FR-5.2 报告中任何 AI 总结都不得脱离证据独立呈现——能一键回到原始讨论。

### FR-6 验证模式（V1，按需触发）
- FR-6.1 输入一个方向 → 跑完整流程 → 输出一份"验证报告"。
- FR-6.2 报告至少包含：扩词结果、信号分类与强度、痛点清单（含频次 / 跨平台数 / 证据）、需求分数、初步小产品方向建议、下一步搜索建议。
- FR-6.3 **弱需求 / 无需求时如实输出**：不编造，明确标"信号不足 / 弱需求"，给出现有的少量证据 + 建议的下一步搜索（参考 NO-GO 思路）。

### FR-7 发现模式（V2，主动发现）
- FR-7.1 维护一个可配置的"狩猎场"：一组固定监控的社区 / 源。
  - **V1 默认狩猎场建议**：独立开发者 / SaaS / 创业 / 开发相关社区（如 Reddit 的 r/SaaS、r/Entrepreneur、r/startups 等）+ Hacker News。理由：数据免费可拿、产出密度高、机会可被个人开发者实现并变现。**狩猎场可插拔，后续可加消费类等其他领域。**
- FR-7.2 定时扫描狩猎场，自动聚类出"反复出现的痛点"，按需求分数排序成"机会卡"。
- FR-7.3 标出"新出现的痛点"和"正在变热的痛点"。
- FR-7.4 节奏：V2 先做"每周一份本周新痛点摘要"（自动调度）。

### FR-8 趋势追踪（V2）
- FR-8.1 持久化存储历次扫描结果，形成时间序列。
- FR-8.2 对每个痛点 / 关键词，标注"变热 / 变冷 / 平稳"。
- FR-8.3 结合 Google Trends 曲线（持续上行 = 真需求；暴涨暴跌 = 可能是一时风口）。
- FR-8.4 区分"被系统 / 大厂功能替代导致的下降"与"市场萎缩导致的下降"——给出判断提示。

### FR-9 BRD / GTM 深度分析（V3，差异化核心）
> 这是"比 DemandHunter 更深"的那一层。**关键原则：每一条 GTM 结论都必须钉在抓回来的真实证据上，而不是 AI 凭空发挥。**

- FR-9.1 **竞品拆解**：定位 2-N 个竞品，抓取它们的定价、以及在 G2 / Capterra / Trustpilot / Reddit / 应用商店上的差评；按"四路搜索"（求助 / 吐槽 / 替代 / 交易）和"五步看法"（1-2 星 / switched from / 3-4 星 / 时间线 / 用户身份）整理出竞品弱点表。
- FR-9.2 **用户画像**：从评论中提炼核心用户身份，画像**必须包含付费意愿**（现在用什么、每月花多少、愿意为更好方案付多少）。
- FR-9.3 **市场规模**：自上而下（行业报告 + 交叉验证 Statista / 上市公司财报 / Crunchbase 融资反推）+ 自下而上（SimilarWeb 流量 × 转化率反推竞品收入），输出 TAM / SAM / SOM。
- FR-9.4 **定价建议**：列出竞品定价 → 取**中位数（不是最低价）** → 应用锚定策略给出"中偏上"定价 + Freemium 免费额度建议（免费额度约"每周用完一次"）。
- FR-9.5 **推广 / 获客渠道**：基于用户在哪出没，给出垂直渠道优先级（如社区 / 插件市场 / 内容），并提示"最大风险通常是获客而非技术"。
- FR-9.6 **GO / NO-GO 决策**：按 §9 框架自动打分并给出建议。
- FR-9.7 最终产物 = 一份**填好的 BRD**（输出规格见 §11）。

### FR-10 报告输出（V1 起）
- FR-10.1 报告输出为 Markdown 文件（可读、可复制、好归档）。
- FR-10.2 报告结构遵循 §11 的 BRD 模板（V1 先填能填的部分，V3 填满）。

### FR-11 简单后台 / UI（V1，轻量）
- FR-11.1 本地可运行的简单后台：发起验证、查看历史报告、查看趋势图。
- FR-11.2 不做登录 / 计费 / 多租户（V1）。
- FR-11.3 历史报告可检索、可对比。

## 6. 非功能性需求（NFR）

> 自用 + 低预算 + AI 辅助开发，是以下所有指标的前提。指标为目标值，可在实现中校准。

### 6.1 性能
- 验证报告：单次端到端目标 **< 3-5 分钟** 完成（受数据源速率限制约束，可异步执行 + 进度提示）。
- 发现 / 趋势扫描：可异步 / 后台 / 夜间运行，不要求实时。

### 6.2 成本（关键约束）
- **数据成本**：V1 仅用免费 / 免费层 / 非商业源，目标趋近于 0。
- **模型成本**：使用高性价比模型；单次验证报告 LLM 成本设上限（如目标 < 约 $0.X/次，实测后定值）。
- **月度预算护栏**：整体控制在每月几美元到小几十美元；超过阈值要能预警 / 暂停（见兜底 §7-成本兜底之外，此处指预算意识）。
- **部署成本**：本地或极廉价部署优先。

### 6.3 可靠性与稳定性
- 单个数据源故障不应导致整次运行崩溃（见兜底 FR/§7）。
- 任务可重跑、幂等；中断后可恢复。
- 长期运行（发现模式）下无明显资源泄漏。

### 6.4 数据合规与平台条款（重点）
- **V1 严格限定在"非商业自用"边界内**：Reddit 等仅用免费层 / 非商业用途；遵守各平台速率限制与 `robots.txt`。
- 明确认知：部分源的抓取可能违反其 ToS、且技术上脆弱（反爬）。这类源标注风险，优先走官方 API / 免费层。
- 仅存储所需的最小数据；自用阶段数据保存在本地。
- **这是迈向"对外卖"前必须重新评估的硬关卡**（商业用途的数据成本与合规完全不同，见 §10）。

### 6.5 隐私
- 自用阶段以本地存储为主，不上传 / 不外发抓取到的用户内容。

### 6.6 可维护性与可扩展性
- 数据源 = 可插拔 adapter；狩猎场、信号词库、意图词、扩词 prompt 等**配置化**，改这些不需要改核心代码。
- 分析流程模块化（扩词 / 采集 / 清洗 / 聚类 / 打分 / 报告各自独立），便于单独调试和替换。

### 6.7 可观测性
- 每次运行记录日志：命中的源、抓取条数、过滤条数、LLM 调用次数与花费、错误与降级情况。
- 便于排查"为什么结果不好"和"钱花在哪"。

### 6.8 安全
- API Key / 凭证放环境变量 / 密钥管理，不写进代码或报告。
- 自用 + 本地，安全要求从简，但凭证管理仍需规范。

## 7. 兜底策略（降级与应急）

> 这一节直接决定工具"稳不稳、会不会偷偷烧钱、会不会给你假结论"。

- **数据源兜底**：某个源失败 / 被限流 → 跳过该源、用其余源继续，并在报告里标注"部分结果（源 X 不可用）"；对瞬时失败用指数退避重试；缓存已抓取结果，避免重复请求浪费配额。
- **抓取脆弱性兜底**：某个抓取 adapter 因目标站改版而失效 → 隔离到该 adapter，自动回退到基于官方 API / 免费层的源；记录告警以便修复。
- **LLM 兜底**：调用超时 / 失败 → 重试；持续失败 → **降级输出**（返回已聚类的证据 + 痛点清单，省略 GTM 叙述层）；可配置主模型 + 备用模型。
- **成本兜底（硬护栏）**：单次运行的 token / 调用次数设硬上限 + 月度预算上限；触顶则**停止并告警**，而不是静默烧钱。
- **弱 / 无需求结果兜底**：找不到强信号时**绝不编造**——明确输出"信号不足 / 弱需求"，附现有少量证据 + 建议下一步搜索（对应 NO-GO 思路）。
- **噪音兜底**：广告 / 榜单 / 目录站 / 机器人内容强过滤；未达"≥3 次 / ≥2 平台"阈值的簇标"未验证"，不冒充真痛点。
- **质量 / 去重兜底**：跨源去重；低置信结论显式标注低置信度，交由人工判断。
- **数据兜底**：本地存储损坏 → 可重建；历史报告与时间序列定期备份。

## 8. 数据源清单与成本

> 核心策略：**自用阶段全部走免费 / 免费层，把数据成本压到趋近 0**；商业化阶段再评估付费源。

| 数据源 | 信号类型 | 接入方式 | 自用（非商业） | 商业化成本 | 阶段 |
|---|---|---|---|---|---|
| Reddit | 抱怨 / 替代品 | 官方 API（OAuth） | 免费层约 100 请求/分钟、月约 1 万次，仅非商业 | 商业层约 $12,000/年起，超出约 $0.24/1000 次，需审批签约 | V1 |
| Hacker News | 抱怨 / 技术求助 | 官方开放 API | 完全免费、无需鉴权 | 同样免费 | V1 |

## 9. 评分与决策框架（GO / NO-GO）

工具的最终决策输出采用此框架（来自 BRD 方法论）：

**GO 条件（满足 ≥3 条建议做）**
- 有 ≥3 个被不同平台验证的真实痛点
- 有明确差异化切入点（竞品没做好的地方）
- TAM 在增长（Google Trends 上行）
- 启动成本可控（< $500）
- 6 个月内可回本

**NO-GO 信号（满足 ≥2 条建议不做）**
- 找不到 ≥3 个真实痛点
- 竞品已做得很好且免费
- 市场在萎缩（Trends 下降）
- 启动成本超出承受
- 没有任何可行获客渠道

## 10. 系统架构与技术选型建议

### 10.1 处理流水线
```
输入(中/英)
  → ① 扩词(LLM, 固定schema)
  → ② 采集(可插拔adapter: Reddit / HN / Trends / ...)
  → ③ 清洗去噪 + 跨源去重
  → ④ 聚类成痛点主题
  → ⑤ 信号分类 + 强度 + 需求分数(应用≥3次/≥2平台规则)
  → ⑥ 证据绑定(链接/时间/互动量/原文片段)
  → ⑦ 报告生成(Markdown, BRD模板)
       └─(V3) 竞品拆解 / 画像 / TAM-SAM-SOM / 定价 / 渠道 / GO-NO-GO
```

### 10.2 关键架构决策
- **数据源抽象层（必做）**：所有源走统一 adapter 接口，便于自用免费源 → 商业源的无痛替换。
- **持久化存储（发现 + 趋势需要）**：验证模式本身是无状态的；但发现模式和趋势追踪要求把数据按时间存下来反复比对。**因此 V1 架构就要预留一个持续积累数据的存储层。**
- **调度器（V2 引入）**：用于发现模式的定时扫描和每周摘要。

### 10.3 技术选型建议（面向 AI 辅助开发）
- 选**主流、生态成熟**的技术栈（AI 辅助开发更可靠），避免冷门技术。
- 单一语言贯穿优先（如 Python，或 TypeScript/Node 全栈）。
- LLM：用高性价比模型，封装在统一调用层，支持主 / 备模型切换与成本上限。
- 存储：V1 用轻量本地数据库（如 SQLite）即可承载报告 + 时间序列；后续再升级。
- 部署：V1 本地运行或极廉价托管。

## 12. 分期路线图

| 阶段 | 主题 | 范围 | 数据成本 |
|---|---|---|---|
| **V1** | 验证型 + 证据链 | 手动输入 → 扩词 → Reddit 免费层 + HN + Trends → 清洗聚类 → 信号分类打分 → 证据绑定 → Markdown 报告 + 简单本地后台。先证明"分析靠谱"。 | 趋近 0 |
| **V2** | 发现型 + 趋势 | 配置默认狩猎场（独立开发者 / SaaS / 创业社区 + HN）→ 定时扫描 → 时间序列存储 → 每周"本周新痛点 / 正在变热"摘要。 | 趋近 0 |

## 13. 风险与待定问题

- **商业数据源成本与合规**：迈向对外卖时，Reddit 商业层 $12k/年起、X 昂贵，需评估第三方数据商或灰色地带——这是"对外卖"能否成立的核心关卡。
- **抓取脆弱性 / ToS 风险**：依赖网页抓取的源易随站点改版失效，且可能违反 ToS；优先官方 API / 免费层。
- **方法论已公开**：信号方法论已被竞品作者公开，护城河只能是"深度（BRD 层）+ 证据可追溯 + 趋势追踪"，需在 V3 持续强化。
- **结果质量**：聚类与打分的准确度需要用真实案例反复调优；初期人工校验扩词与结论。
- **待定参数**：模型选型与单次成本上限的具体数值、月度预算阈值、狩猎场具体社区清单、需求分数的权重公式——这些在 V1 实现中校准。
